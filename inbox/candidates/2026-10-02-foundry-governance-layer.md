# Candidate: Foundry governance layer

Status: candidate
Date: 2026-10-02

UIGS-Foundry should have one thin highest-level governance document.

Purpose:
- define scope and non-goals;
- define evidence and source-of-truth rules;
- define Candidate -> Validated -> Canonical promotion;
- define provenance and change requirements;
- resolve conflicts between UI grammar, reliability, operations, and project cases.

It should not prescribe detailed UI, platform code, test cases, or project-specific implementation.

Existing project principles are the primary source material. Do not create a second competing doctrine; distill the stable cross-project principles into the Foundry charter and keep detailed rules in lower layers.

Single observations may create candidates or evidence, but must not silently rewrite canonical rules.
