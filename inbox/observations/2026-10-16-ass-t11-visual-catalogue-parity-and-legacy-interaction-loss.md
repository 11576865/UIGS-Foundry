Date: 2026-10-16
Status: Observation / Design review; **PENDING design restoration and owner review**, not Canonical
Design: https://www.figma.com/design/5yNY5dMnmpmaOnYxDlEhY5
Product repo: https://github.com/11576865/ASS-Workbench-Android
Previous Figma evidence: `inbox/cases/2026-10-16-ass-tablet-t1-figma-task-semantic-seven-screen-prototype.md`; `inbox/observations/2026-10-16-ass-tablet-t11-source-severity-separation-karaoke-quantization-and-adaptive-drawer.md`

## Prompt and bounded conclusion
The owner raised an explicit coverage concern: "UI是不是没有完全显示所有重要功能？还抛弃了之前的一些突破性进步？" A direct crosswalk of the already visually verified T1.1 nine Figma frames and the current `WorkbenchToolCatalog.kt`, `docs/MULTI-UI-CAPABILITY-MIGRATION-2026-10-11.md`, `docs/UI-EXPERIMENT-240-LEDGER.md`, the 2026-10-01 user-provided UI constitution, and 10-13/10-14 ASS reports supports **yes: incomplete design coverage and major missing representations of legacy interactions**. This is a Figma *design parity* finding, NOT evidence that domain code is deleted.

## Evidence / live crosswalk
- Nine native-editable Figma frames cover: FIXED Position/preview/inspector, dedicated timeline, Effects, Karaoke, one Event Raw before/after review, SPATIAL illustration, 18-tool index, and 1024×768 compact/editor-drawer pair. The 18-item tool catalogue and 66 reaction-bearing prototype nodes do not equate to 18 working tool interactions. The directory's grounded destinations are materially narrower (TIMELINE, POSITION, EFFECTS, KARAOKE); other entries are mostly design text. Selected Event #39 is the only modelled drawer event whose click returns to a matching editor; others are display only and intentionally not bound.
- `WorkbenchToolCatalog.kt` defines 18 persisted tool IDs across ten task groups. Mainline `WorkbenchTask` includes **TEXT / 正文** as a first-class task; the T1.1 persistent rail lacks this explicit task. TEXT/Event metadata/Style authoring, batch Filter→Transform→Preview→Commit, fonts/font requirements, QC/compatibility/diagnostics, PROJECT (ASS/.asswb/SRT/MKV resources), vector clip and extensive Position transforms have no end-to-end Figma task screens.
- The Figma Position inspector shows Event override provenance, but not a complete **Read Source vs Write Target** choice, Shared Style reference impact, Focus/Selection/PinnedEvent binding and failure states, nor multiple simultaneous inspectors with distinct bindings; one selected Event is shown as if the sole authoring context.
- T1.1 SPATIAL shows a dot-grid world, one preview, one event list, one inspector, a bottom timeline and a five-button **left** bookmark rail, but no full four-edge temporary/persistent layers, docking/tab grouping/minimize, tool instance spawn/copy/pin/rebind/hidden recall lifecycle, semantically scaled world, actual camera navigation/back/forward/offscreen cues, gesture-based spatial geometry manipulator or precision lens states. One spatial picture is not a complete replacement for the former experimental interaction vocabulary.
- Source audit `docs/MULTI-UI-CAPABILITY-MIGRATION-2026-10-11.md` already distinguishes migrated live production interactions from **gaps in current Host consumers**: four-edge panel orchestration/side/order, original Surface dock/minimize/tabs and real glass material/blur/click-through, etc. Some old prototypes were never fully production-grade, and some preserved models still lack consumers. Therefore do not claim all innovations were previously shipped or subsequently deleted; tag each as (A) current implemented/reachable, (B) partial implementation or only legacy model, (C) design-only intent, with implementation/visual/device evidence separately.
- The 2026-10-01 UI constitution calls for one domain core with alternative Hosts, same tool identity and Binding across surface transitions, 4 distinct state owners, explicit write target, interaction proxy/precision and semantic density, multi-step dialogs only when required, preview/commit/Undo separation, distinct save objects (ASS/.asswb/SRT/MKV), and dynamic status evidence. A catalogue index alone is not fidelity to those behaviors.

## Corrective design acceptance gate (Candidate, not automatically Canonical)
Before naming T1.x a complete or final UI design, create a **capability-to-surface parity matrix** with columns: (stable Tool ID; actual task path; source object/Binding/Selection/Focus; read source + write target; Figma state & gesture transitions; old capability inheritance / intentional retirement; current production UI consumer; current code tests; visual evidence; device evidence; status). Missing tool screens or inactive interactions must remain visibly Pending, not silently green from catalogue presence.

Restore at minimum in design (not necessarily immediately in Android code): TEXT/Raw + shared Style & local override flows; Batch and QC; Project/resources and save target differentiation; multi-object selection; geometry manipulators/precision feedback; tool instance lifecycle and cross-Host rebinding; four-edge/timeline and dock/tab/glass interactions as accepted/deferred rather than erased; spatial navigation states; real source/target/failure/draft conflict variants. Prototype an editable workflow and its failure/recovery states, not only a mock still.

Owner must decide intentional deprecations separately; no automatic restoration of 8 retired entire UI variants or promotion of 240 hypothetical items to completed functionality. T1.1 Figma remains a candidate rather than a design freeze. R3 native implementation PR #148 being Draft remains separate from T1.1 parity and does not establish T1.1 Android delivery.
