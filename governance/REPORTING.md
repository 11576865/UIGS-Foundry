# Reporting policy

Status: **Canonical**

Reports should be generated from structured facts whenever feasible and must distinguish source facts, derived metrics, agent/model analysis, and unresolved evidence.

Generated reports must state generation time or source revision and must not silently present stale project state as current.

Preferred families include project engineering state, release readiness, CI/red reasons, stress/regression coverage, GitHub Actions resource policy, architecture/dependency state, known limitations, cross-project reuse, UI conformance, and agent/repository coordination.

Narrative analysis may summarize structured records but must not overwrite provenance or evidence level.
